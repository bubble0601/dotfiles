# layout: visual(図解ペライチ)

内容を知らない人に、実画面に近いモック図を中心に説明するページ。spec の `sections` から build.py が組む。

## 種別(spec の `kind`)

| kind | 使う場面 | 質問の回答欄 |
|---|---|---|
| `proposal` | 判断・回答・意見を返してもらう(企画・仕様の提案、ヒアリング) | あり |
| `general` | 読むだけ(機能紹介、操作説明、リリース告知) | なし(`questions` を書くと build.py がエラーにする) |

## 出来上がりの形

### 共通

- 軸はトピック(章)。章ごとに **図 → ポイント(3 つ) → 注意点** の順
- 図は **実画面に近いモック**(ヘッダ・左ペイン・カード・ダイアログを実装の見た目で描き、変わる部分や見てほしい部分に番号つき吹き出し)。概念図(タイムライン・比較)は冒頭や補足にだけ使う
- 「過去の分は変わらない」類の当たり前の注意点は書かない
- 最下部の注釈やフッターは置かない

### `general`

- 章の見出しは「〜できる」「〜の流れ」など、読み手が何を知れるかで付ける
- ラベルの既定は「ポイント」「注意点」(`points_label` / `notes_label` で変えられる)

### `proposal`

- 章は「課題」。課題ごとに **図 → できるようになること(3 つ) → きいておきたいこと(質問 + 回答欄) → この仕様の留意点(対応できない・不便な点)** の順
- 判断事項を表で並べない。判断は決め打ちして本文に溶かし、決め打ちで困る点だけ「留意点」に出す
- 質問は「答えによって設計が変わるもの」だけ。1 課題 1〜2 問が目安
- 全体の章(スコープ・工数・共通の留意点)は最後に短く

## 手順

1. **中身を決める**: 章ごとに 図の内容 / ポイント 3 つ / 注意点(`proposal` は質問も)を箇条書きで固める。金額・氏名は架空で、計算は実際の規則に合わせる
2. **実画面の見た目を調べる**(初回のみ): Explore agent に「ヘッダ・ページ背景・カード・ボタン・フォーム・ダイアログ・対象画面の構造・色トークン(hex)・フォント」を実装コードから拾わせ、`assets/app-shell.css` の `:root` 変数(`--brand` / `--page` / `--ink` / `--line` …)を差し替える。画面固有の部品(擬似テーブルの列幅、タブの形など)はモック側の `<style>` で足す
3. **図を HTML で描く**: 1 枚 = 1600×900 固定の HTML(`examples/mock_*.html` を複製)。吹き出しは `.co`(青 = 新しく増える・見てほしい部分、`.co.warn` = 注意点)。ダイアログは `.dlg`(既定 `left:42%` で右に吹き出しの余地がある)
4. **描画**: `PYTHON=<Pillow 入り python> scripts/render.sh <out_dir> a.html b.html ...` → 2x PNG と JPEG(q88)。Pillow は venv に入れる(`python3 -m venv .venv && .venv/bin/pip install Pillow`)。base64 で約 1.35 倍になるので、ページ全体のサイズ条件(SKILL.md)に入るよう枚数と品質で調整する
5. **1 回だけ目視**: 全図を 1 枚のコンタクトシートにして Read で確認 → はみ出し・重なりを 1 回で直す(再確認はしない)
6. **spec を書く**: `examples/spec.<kind>.example.json` を複製する
7. `proposal` で計画書がある案件なら、ページ作成中に出た人間の決定を計画書の決定一覧に記録して stage する

## 図の描き方の勘所

- 文字は 26〜44px、1 枚に伝えることは 1 つ。「いま / これから」の対比は左右 2 パネル(`assets/figure.css`)
- 吹き出しは画面の主役(変わる行・入力欄)を隠さない位置に。表やカードが画面いっぱいに広がる画面では、モック側で幅を絞って(例: `.box{width:760px}`)右に余白を作り、吹き出しは指す行と同じ高さに置く。ダイアログは `left:42%` で右に余白ができる
- モックの数字は整合させる(明細の合計 = 各行の和)。実装が既に持つ挙動(0 円の行を出す、根拠の Tooltip など)は再現する
- 描画後に下端が切れていたら、ダイアログの `top` を小さくし表の padding を詰める
