# ペライチ Artifact

## ユーザー入力

```
$ARGUMENTS
```

空でなければ最優先で考慮する。

## いつ使うか

- 内容を知らない人(PO、顧客、他チーム、利用者)に、画面の図を中心に説明したい
- 1 ファイルで配れる HTML が要る(画像も埋め込み)。**サイズは 1 MB 以上 10 MB 以下にする。Slack に貼ったときにプレビューが出る条件**なので、下回れば図を増やす・JPEG の品質を上げる、上回れば品質を下げる(build.py が範囲外なら警告する)

## 資料の種別を決める(最初に必ず)

spec の `kind` で切り替える。ユーザーが種別を指定していればそれに従う。

| kind | 判定基準 | 例 | 質問の回答欄 |
|---|---|---|---|
| `proposal` | 読み手に判断・回答・意見を返してもらう | 企画・仕様の提案、ヒアリング資料、レビュー依頼 | あり |
| `general` | 読み手は読むだけで、返事を求めない | 機能紹介、操作説明、仕組みの解説、リリース告知、調査報告 | なし |

選択コメントと「全入力内容をコピー」はどちらの種別にも付く。

- 依頼文に「意見をもらいたい」「確認してもらう」「決めてもらう」「ヒアリング」があれば `proposal`
- 判定がつかないときは、作り始める前にユーザーに確認する
- 決めた種別は、作業開始時にユーザーへ 1 行で伝える

## 出来上がりの形(この形から外れる指示があればそちらを優先)

### 共通

- 軸はトピック(章)。章ごとに **図 → ポイント(3 つ) → 注意点** の順
- 図は **実画面に近いモック**(ヘッダ・左ペイン・カード・ダイアログを実装の見た目で描き、変わる部分や見てほしい部分に番号つき吹き出し)。概念図(タイムライン・比較)は冒頭や補足にだけ使う
- 「過去の分は変わらない」類の当たり前の注意点は書かない
- 最下部の注釈やフッターは置かない
- 下部バーは「全入力内容をコピー」だけ。コピーには入力したもの(回答・コメント)だけが入る(未回答は除外)

### `general`

- 章の見出しは「〜できる」「〜の流れ」など、読み手が何を知れるかで付ける
- ポイントの既定ラベルは「ポイント」、注意点は「注意点」(`points_label` / `notes_label` で変えられる)
- `questions` は使えない(build.py がエラーにする)

### `proposal`

- 章は「課題」。課題ごとに **図 → できるようになること(3 つ) → きいておきたいこと(質問 + 回答欄) → この仕様の留意点(対応できない・不便な点)** の順
- 判断事項を表で並べない。判断は決め打ちして本文に溶かし、決め打ちで困る点だけ「留意点」に出す
- 質問は「答えによって設計が変わるもの」だけ。1 課題 1〜2 問が目安
- 全体の章(スコープ・工数・共通の留意点)は最後に短く

## 手順

1. **種別を決める**: 上の基準で `general` / `proposal` を決める
2. **中身を決める**: 章ごとに 図の内容 / ポイント 3 つ / 注意点(`proposal` は質問も)を箇条書きで固める。金額・氏名は架空で、計算は実際の規則に合わせる
3. **実画面の見た目を調べる**(初回のみ): Explore agent に「ヘッダ・ページ背景・カード・ボタン・フォーム・ダイアログ・対象画面の構造・色トークン(hex)・フォント」を実装コードから拾わせ、`assets/app-shell.css` の `:root` 変数(`--brand` / `--page` / `--ink` / `--line` …)を差し替える。画面固有の部品(擬似テーブルの列幅、タブの形など)はモック側の `<style>` で足す
4. **図を HTML で描く**: 1 枚 = 1600×900 固定の HTML(`examples/mock_*.html` を複製)。吹き出しは `.co`(青 = 新しく増える・見てほしい部分、`.co.warn` = 注意点)。ダイアログは `.dlg`(既定 `left:42%` で右に吹き出しの余地がある)
5. **描画**: `PYTHON=<Pillow 入り python> scripts/render.sh <out_dir> a.html b.html ...` → 2x PNG と JPEG(q88)。Pillow は venv に入れる(`python3 -m venv .venv && .venv/bin/pip install Pillow`)。図は合計 1〜4 MB が目安で、base64 で約 1.35 倍になる。ページ全体が 1〜10 MB に入るよう枚数と品質で調整する(Slack プレビューの条件)
6. **1 回だけ目視**: 全図を 1 枚のコンタクトシートにして Read で確認 → はみ出し・重なりを 1 回で直す(再確認はしない)
7. **組む**: `examples/spec.<kind>.example.json` を複製して中身を書き、`scripts/build.py spec.json out.html`
8. **公開**: Artifact ツールで `out.html` を publish(`icon` は初回だけ)。以後は同じパスで republish。ローカルで開く人向けの `<meta charset>` は build.py が入れる
9. `proposal` で計画書がある案件なら、ページ作成中に出た人間の決定を計画書の決定一覧に記録して stage する

## 図の描き方の勘所

- 文字は 26〜44px、1 枚に伝えることは 1 つ。「いま / これから」の対比は左右 2 パネル(`assets/figure.css`)
- 吹き出しは画面の主役(変わる行・入力欄)を隠さない位置に。表やカードが画面いっぱいに広がる画面では、モック側で幅を絞って(例: `.box{width:760px}`)右に余白を作り、吹き出しは指す行と同じ高さに置く。ダイアログは `left:42%` で右に余白ができる
- モックの数字は整合させる(明細の合計 = 各行の和)。実装が既に持つ挙動(0 円の行を出す、根拠の Tooltip など)は再現する
- 描画後に下端が切れていたら、ダイアログの `top` を小さくし表の padding を詰める

## ページ側の仕様(page.js)

- 回答・コメントは `localStorage`(キーは spec の `storage_key`)に自動保存。共有はされない(他人に見せるなら「全入力内容をコピー」で回収)
- 本文の文字を選択するとその場にコメント欄。保存すると橙のハイライト(`::highlight(memo)`)。ハイライトをクリックすると編集・削除。Chrome / Edge / Safari 17.2+ でハイライト表示、非対応でもコメント自体は付く
- 下部バーは、マウス環境では画面下端から 48px 以内にカーソルが来たときに出て、バーより上にカーソルが移ると消える。Tab でフォーカスしても出る。タッチ環境(hover なし)は常に出す
- コピー形式は Markdown(`## 課題名` → `### 質問 n: …` / `回答: …` → `### コメント: 「引用」` / 本文)

## ファイル

- `scripts/render.sh` 図の描画、`scripts/build.py` ページ生成(spec JSON → HTML)
- `templates/page.css` ページの見た目、`templates/interactive.css` / `page.js` 回答欄・選択コメント・下部バー
- `assets/app-shell.css`(実画面風。`:root` の変数で配色を差し替える)、`assets/figure.css`(概念図)
- `examples/spec.general.example.json` / `spec.proposal.example.json`、`examples/mock_app_screen.html`、`examples/mock_dialog.html`、`examples/figure_concept.html`、`examples/img/`(その描画結果)
